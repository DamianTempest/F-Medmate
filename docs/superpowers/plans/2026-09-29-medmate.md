# Medmate Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. User authorised inline completion.

**Goal:** Deliver a tested, complete local KivyMD health companion.
**Architecture:** SQLite repository owns authentication and participant access. Independent health/API services contain no widgets. KivyMD screens render repository results and make asynchronous online requests.
**Tech Stack:** Python 3.12 (tested), Kivy 2.3.1, KivyMD 1.2.0, SQLite, requests, python-dotenv, pytest.
**Spec:** ../specs/2026-09-29-medmate-design.md

## Global Constraints
- Local prototype first; no Community in doctor mode.
- Kivy 2.3.1 and KivyMD 1.2.0.
- No embedded secrets, legacy personal data, virtual environments, or generated binaries.
- No diagnosis, prescribing, fabricated replies, or false remote delivery claims.
- Online work must not block UI or update another user's session.

## Review Focus
- Unlink while doctor accesses records: revoke at database boundary.
- Two appointments in same doctor/time: reject conflicting booking.
- Unknown allergy: refuse suitability claims.
- Malformed/timeout AI response: useful error and retry path.
- Logout with pending response: ignore result in later session.
